01

问题不是“不认识情绪”，是“没有练习场”

自闭症谱系障碍（ASD）青少年的核心困难之一，是把社交规则用到具体情境里。 这件事需要大量、重复、带反馈的练习。而现实是：练习机会集中在机构课时里，一周两三次， 每次几十分钟，而且场景固定。

供给侧：人工引导不可复制

特教老师、行为分析师、家长轮流承担引导角色。同一句“怎么开口借笔记”， 在不同人那里得到不同反馈，孩子学到的往往是“这一次怎么说”，而不是“这类场合怎么应对”。

场景侧：真实社交有代价

在真实场合失败一次，代价是关系、情绪和自信心。孩子因此回避，练习量进一步下降—— 这是最需要被打破的循环。虚拟练习的价值不是“仿真”，而是允许失败和重来。

记录侧：练过什么、卡在哪，没人记得

家长凭印象，老师凭课堂观察，跨周对比几乎不可能。没有记录，就没有“上次会了、这次换个场景又不会” 这种最有价值的泛化信息。

02

研究依据：先看证据，再决定做什么

这一节只放能在原文核对到的数字与结论。检索日期 2026-11-21， 来源为 PubMed 题录与摘要、ABIDE 官网；每条给 PMID 或 DOI，路演被追问时可当场查。

三条会直接改变设计的结论

一，不做诊断。数字表型筛查的阳性预测值只有 40.6%（Nat Med 2023）， 我们只做练习与记录。
二，不训练模型。没有中文青少年社交脚本标注集，用未成年人数据训练还涉及单独同意与伦理审查； 两天内用「规则脚本 + 受约束 LLM」就够。
三，不把眼神接触当目标。看眼睛的时长在婴儿期是逐渐下降的，不是一开始就缺失（Nature 2013）； 强迫注视既缺证据支持，也违背神经多样性立场。

由此定下的产品立场

不做「眼神接触训练器」，做「可预测的社交演练场 + 解读意图的脚手架 + 随时可退出的安全空间」。 每条脚本都保留「拒绝/离开」选项且不扣分；反馈说「这句话可能让对方以为……」，不说「你错了」。

03

四个模块，两个做透，两个做小

48 小时容不下“平台”。我们按“能不能现场演示、能不能说清价值”来砍： 模拟对话和练习记录做完整闭环，情绪练习和泛化任务做可用最小版。

社交脚本模拟对话 48h 完整闭环 细节

分场景脚本树 + 可选 LLM 自由模式。每一回合给出“对方回应”与针对性反馈， 重点不是打分，而是让孩子看见换一个说法，对方的反应会怎么变。
  • 首批 6 个场景：借笔记、被拒绝后的回应、撞到人的道歉、课堂提问、加入同学聊天、打电话请假。
  • 回合结构：情境说明 → 3 个候选说法（含 1 个“容易出问题”的真实选项）→ 对方回应 → 反馈与下一步提示。
  • 脚本优先，LLM 兜底：演示走本地脚本树（断网也能跑）；LLM 只在教师监护开关开启时用于自由追问。
  • 反馈文案规则：不评价人，只评价说法；不用否定性形容词；每次给“再试一次”和“换个说法”两条出路。

验收标准：任一场景能连续跑完 ≥5 回合，选择、回应、反馈、记录四步都在；断网可完整演示。

学习与情绪记录 48h 完整闭环 细节

每次练习自动留痕：场景、回合、选择分布、耗时、当时情绪自评。 这是教师端和家长端唯一必需的数据来源。
  • 情绪自评用五档图形量表（很不安 → 很平静），不要求写文字，降低表达负担。
  • 记录页只回答三个问题：练了什么、和上次比怎样、下次建议练什么。
  • 导出 CSV / 打印视图，方便老师贴进个别化教育计划（IEP）材料。
  • 记录默认不含可识别信息，演示用合成数据。

验收标准：完成一轮练习后，记录条目出现在列表与概览中，且能按场景聚合。

情绪与情境判断练习 48h 最小版 细节

刻意不做“读脸训练”。用情境 + 线索判断对方可能的感受， 练的是推断，不是辨认五官。
  • 题库 12–20 题：一段情境描述 + 4 个情绪选项 + 一句线索提示。
  • 答错不弹红叉，只补一句“还有另一种可能：……”。
  • 不用真人人脸照片：插画或文字情境，减少隐私与“被扫描”的不适。
  • 可选的人脸情绪模型只作为辅助反馈，不做身份识别、不存原图。

为什么这样设计：ASD 情绪识别训练能否迁移到真实社交，文献结论并不一致。 我们不宣称“提高共情”，只记录“这类情境判断的正确率与反应时是否随练习变化”。

泛化任务卡 48h 最小版 细节

把线上练的那句话搬到线下用一次。这是产品价值的关键一跳， 但 48 小时里只做“发任务—打卡—回看”。
  • 教师从场景库一键下发，例如“本周在食堂向一位同学说一句话”。
  • 打卡方式：一句话描述 + 情绪自评（不强制拍照，避免隐私与压力）。
  • 记录页把“线上练了几次”和“线下用了几次”并排显示——这是我们最想给评委看的一张图。

验收标准：下发→打卡→并排展示三步可演示。

明确不做 本期排除 为什么

砍掉的理由不是“没时间”，而是“不该由我们做”或“风险大于价值”。
  • 诊断与筛查量表结论：没有临床资质与授权，不做任何“是否 ASD”“严重程度”输出。
  • 无边界自由聊天：面向未成年人的开放对话不可控，自由模式必须挂在教师监护开关下。
  • 眼神接触训练：把“看眼睛”当目标是错误的干预方向，我们不内置。
  • 强激励与连续打卡惩罚：不做断签提醒、排行榜、成瘾式奖励；奖励低刺激且可关闭。
  • 多人房间 / 同伴演练：需要教师在场才安全，放到赛后。
  • 原生 App：双端开发 + 上架审核 + 推送，三人两天做不完；网页 + PWA 足够。

06

三人分工：一人一条主线，交叉处写文档

A · 前端与体验 网页

负责：页面结构与交互、脚本树渲染引擎、无障碍与感官友好设置、教师/家长视图界面、路演页面本身。

交付：学生端 4 屏 + 教师端 2 屏 + 可访问性检查表（键盘、对比度、动效可关、无自动播放）。

不做：不碰数据库迁移、不决定内容文案（由 C 定）。

B · 后端与数据 API

负责：API 与数据模型、Provider 抽象（对话 / 可选情绪模型）、记录与聚合、导出、部署与限流。

交付：OpenAPI 文档 + 可替换的 AI 接入层 + 合成数据集 + 一键启动脚本。

不做：不自己写场景脚本；不在未确认前接入任何采集人脸的能力。

C · 内容、审核与对外 质控

负责：场景脚本与题库撰写、反馈文案规则、审核队列与拦截词表、知情同意与隐私说明、 特教老师咨询对接、路演主讲与问答。

交付：脚本规范（JSON Schema）+ 6 个场景 + 12 道情境题 + 审核记录表 + 讲稿。

不做：不写业务代码，只在内容层用结构化数据提交。

交叉规则（避免三天后互相卡住）

  • 数据格式先定后写：C 提交脚本 JSON，A/B 都不改字段含义，只加校验。
  • 每 4 小时一次 10 分钟对齐，只讲“能不能演示”，不讲进度百分比。
  • 每个关键模块至少两人看过；单点风险最高的记录聚合逻辑由 B 写、A 复核。
  • 砍功能的决定权在检查点会议，不在个人。
07

架构：网页优先，AI 能力可换供应商

学生端 · 网页

为什么是网页，不是软件（App）

两天周期下的成本对比
维度网页（我们的选择）原生 App
开发量一套代码，桌面/平板/手机通吃双端两套 UI，两天做不完
分发发个链接，评委和机构当场能打开上架审核周期以周计，演示拿不到
迭代改文案改脚本刷新即生效每次改动走构建与审核
离线PWA 缓存脚本，断网可演示原生离线更强，但我们不需要
能力需求文字 + 图片 + 可选语音，网页足够只有需要后台定位/相机常驻时才值
结论网页 + PWA。真要用 App 形态，赛后用 Capacitor 包一层即可，架构不变。

要不要专门训练一个模型？

不训练。三个理由同时成立：没有中文青少年社交脚本标注集；用未成年人敏感数据训练模型要走监护人单独同意与伦理审查，两天做不完；证据也不支持——技术类干预的效应量只有 g=0.33，真正起作用的是结构化练习与成人反馈，不是模型规模。

三种做法，只选一种
方案两天内能否交付主要风险结论
纯规则脚本树能表达略生硬，但完全可测、可离线作为主路径保留
规则 + 受约束 LLM能需输出校验与超时降级选它
微调 / 自训模型不能无数据、伦理审查、算力与记忆风险不做

LLM 只做两件事：把审核过的脚本改写得更自然；把孩子的自由输入归类到已有选项。不让它自由生成反馈。API Key 只放服务端环境变量，前端永远拿不到；超时或限流自动回落到规则层。

伦理不是附录，是这个产品能不能存在的前提

“我们做的东西面向一群无法完全自主表达同意的未成年人。 如果隐私和措辞没想清楚，功能做得越好，伤害越有效率。” 队内讨论共识，写进开发规则：任何采集字段的新增，需 C 复核用途与保留期

同意与撤回

监护人书面同意 + 学生本人适龄说明（能看懂的一页版）。同意记录独立成表， 撤回即触发删除，删除有日志可查。黑客松阶段只用合成数据，不接触任何真实用户数据。

数据最小化

  • 不采集人脸、不采集精确位置、不采集录音原件（语音功能若做，只留转写文本）。
  • 练习文本去标识后存储；姓名与标识符分离保存。
  • 不接第三方广告与分析 SDK；导出只给教师/家长，不给平台方留长期副本。

内容安全

三重限制：场景白名单 → 输出模板约束 → 敏感词与话题拦截。 自伤、被欺凌、求助类关键词触发时停止生成，改为展示求助指引并通知监护人/教师（预设话术，不做判断）。

措辞与立场

统一使用“自闭症谱系障碍 / ASD”“神经多样性”，不用“患者”“缺陷”“治愈”。 产品目标是让孩子在社交场合更从容，不是把孩子训练得像非自闭症的人。 界面不强制眼神接触、不惩罚回避、奖励可关闭。

人工审核

新场景、新题、提示词变更一律进审核队列，由 C 复核后灰度上线； 审核记录可追溯，出错内容能一键回滚。这是“审核”这条分工线存在的理由。

合规与研究

依《个人信息保护法》《未成年人保护法》《数据安全法》执行； 若后续用于研究或采集效果数据，需学校伦理审查与数据使用协议，量表使用需授权。相关条文与版权待逐条核实。

赛后三个月：从演示品变成有人用的东西

  1. 第 1–2 周

    一手需求验证

    访谈 5 位特教老师 + 5 位家长，重写脚本；确认“泛化任务卡”是否真是关键一跳。

    C 主责产出：访谈记录与脚本 v2
  2. 第 3–4 周

    机构小试用（1 个班级，4 周）

    签数据使用与同意书，只留练习与情绪自评记录；教师每周给一次真实场景使用评定。

    B 部署A 教师视图
  3. 第 5–8 周

    把“泛化达成率”变成真指标

    定义口径：同一场景线上练习次数 vs 线下任务卡达成率；看是否随练习上升。

    这是产品能否继续的核心证据
  4. 第 9–12 周

    难度自适应与语音输入

    部分孩子书写吃力，语音输入优先级高于自适应；多人房间必须有教师在场机制才做。

    A + B

指标口径（先写清，避免赛后自吹）

  • 使用侧：周练习次数、单场景复练率、平均时长。
  • 学习侧：回合目标达成率、情境判断正确率与反应时、跨场景迁移表现。
  • 泛化侧：任务卡完成率、教师评定的真实场景使用次数（1–5）。
  • 体验侧：感官负荷主观评分、“愿意继续用”评分、家长/教师满意度。
  • 安全侧：审核拦截数、误放行数（目标 0）、危机提示响应时长。
  • 不宣称：核心症状改善——无临床验证与授权，不做这个结论。
