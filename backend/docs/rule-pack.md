# 星桥负规则包（说什么 / 不说什么）

版本：`2026-11-21.1`
规则文件：`app/rules.py`
证据：`data/rule_evidence.json`（BCC 命中计数，不含原文）

## 这是什么

给「开放式陪伴」用的输出侧护栏：**模型生成的每一句话，在发给用户之前先过一遍规则**。

- `allowed: false`：这句话不能发，必须重写或换成安全表达。
- `hits`：命中了哪条规则、命中了哪个词、为什么不行。
- `safeAlternatives`：同一情境下可以说什么。

注意：它检查的是**模型要说的话**，不是用户输入。用户输入里的自伤/暴力风险仍走原来的审核队列。

## 怎么接

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/safety/check \
  -H 'X-Admin-Token: <token>' -H 'Content-Type: application/json' \
  -d '{"text":"自闭症是可以治愈的。"}'
```

```json
{
  "allowed": false,
  "hits": [{"ruleId":"cure-01","category":"cure_narrative","severity":"block",
            "matched":"治愈","why":"...","sayInstead":["..."]}],
  "safeAlternatives": ["社交能力可以练，但我不替你下“治好”的结论。"],
  "rulesVersion": "2026-11-21.1"
}
```

推荐流程：

```python
draft = llm_reply(...)                 # 任何供应商
verdict = POST("/api/v1/safety/check", {"text": draft})
if not verdict["allowed"]:
    draft = regenerate(...)            # 先重写一次
    if not POST("/api/v1/safety/check", {"text": draft})["allowed"]:
        draft = verdict["safeAlternatives"][0]   # 仍不过就用安全模板
send(draft)
```

规则目录：`GET /api/v1/rules`（管理员），返回全部规则、严重度和 BCC 证据。

## 可以说什么（全局安全短语）

- 我在，你慢慢说。
- 不想说也可以，我们可以先停一下。
- 你现在是什么感觉？可以只选一个词。
- 这件事听起来很难受。
- 你愿意的话，我们可以一起想下一步。
- 你可以拒绝，也可以随时离开。
- 我不替你下结论。
- 需要的话，我帮你找可信任的大人。

## 边界

1. **正则只能抓显式表达**。换一种说法（“你这种状态不太对劲”）可能漏过。它必须和人工审核、模型自检叠加，不能当成唯一防线。
2. **规则是产品立场，不是临床指南**。加规则由内容审核（C）拍板，改完跑 `pytest tests/test_rules.py`。
3. **BCC 计数只用于证明“这些话真的存在”**，不代表规则覆盖了全部语料；`data/corpus/` 不随包分发。
4. 规则版本会写进每次响应；线上出问题时可定位到具体版本。

## 更新流程

1. 在 `app/rules.py` 增加/修改规则，写清 `why` 与 `sayInstead`；
2. 补一条正例和一条反例到 `tests/test_rules.py`；
3. `pytest -q` 全绿；
4. 重跑 `scripts/rule_evidence.py` 更新 BCC 计数；
5. 版本号加一，通知接入方拉取 `/api/v1/rules`。
